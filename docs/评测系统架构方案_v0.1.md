# 量子化学科学计算质量智能评测系统 — 架构方案 v0.1

> 本文是"搭架子"阶段的定稿草案。目标不是把模型做完，而是先钉死**契约**和**落地顺序**，
> 让后面无论换模型、换体系、换人接手，骨架都不用动。

---

## 0. 已敲定的四个前提

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 系统定位 | **双模式、同一内核**：离线批量复盘 + 在线流式拦截，核心只有一个 `evaluate()` |
| 2 | 数据来源 | **公开数据集先行**（有高精度参考、样本量大）+ **自有 Gaussian 体系补充**（只做测试集/泛化验证） |
| 3 | 首发输出头 | **两个**：误差回归（带 σ）+ 复核决策；质量评分由前两者推导，异常诊断 v0.1 交给规则引擎 |
| 4 | 输入表示 | **表格标量特征 + 结构描述符**（兼容 TabPFN/XGBoost，同时不丢 3D 信息） |

---

## 1. 系统边界

```
工作流产物 ──► evaluate(record) ──► EvalResult ──┬──► 离线：汇总成评测报告
                                                 └──► 在线：转成动作（建议/拦截/加算）
```

- 两种模式**共用同一内核**，差别只在"批量还是流式"和"动作是否真的执行"。
- 在线模式内部再分两级，由一个配置开关控制，**默认 advisory**：
  - `advisory`：只输出建议（"建议调参重算"），由上层工作流自己决定执不执行；
  - `enforcing`：内核直接改写参数/拦截（第 3 页的"调整收敛参数并重启"属于这一级）。
- 延迟预算：规则引擎 < 50 ms，模型前向 < 200 ms。**规则引擎必须能在模型挂掉时独立给出结论**。

---

## 2. 分层与职责

| 层 | 名称 | 职责 | 关键产物 |
|---|---|---|---|
| L0 | 采集层 | 解析 Gaussian/ORCA 输出，规范化成 `CalculationRecord` | schema 带版本号 |
| L1 | 特征层 | 阶段标量特征 + 结构描述符 + 体系化学空间标签 | 一张宽表，可直接喂 XGBoost/TabPFN |
| L2 | 规则引擎 | 有明确科学标准的确定性判定 | `RuleHit[]`，每条带 fix_hint |
| L3 | 模型层 | 共享编码器 + 两个输出头（v0.1），预留四头挂载位 | `error_pred`, `sigma` |
| L4 | 决策层 | 在 DFT 预算约束下把判定翻译成动作 | `Action` + `reasons[]` |
| L5 | 闭环层 | 参考值回灌、概率校准、漂移监控 | 校准版本号、监控报表 |

**判定层是并联，不是串联。** 规则命中即出结论且不进模型；规则未覆盖的样本交给模型；
模型 σ 超阈值时**回退**给规则/人工，而不是硬给一个结论。理由：规则漏掉的恰好是模型最该发现的，
而模型最没把握的恰好最该退回确定性检查。

## 3. 两个核心契约（先钉死，其余都围着它转）

### 3.1 `CalculationRecord`（输入）

```jsonc
{
  "record_id": "uuid",
  "schema_version": "0.1",
  "stage": "opt | scf | freq | single_point",
  "system": {
    "formula": "C12H18O4TiCl4",
    "n_atoms": 42, "charge": 0, "multiplicity": 1,
    "family": "internal_donor | titanium_complex | organic | surface"
  },
  "method": {
    "software": "gaussian16", "functional": "B3LYP",
    "basis": "def2-SVP", "dispersion": "D3BJ", "solvent": null
  },
  "scalars": {
    "e_total": -1234.5678,
    "e_homo": -0.21, "e_lumo": 0.03, "gap": 0.24,
    "grad_norm_max": 0.00042, "grad_norm_rms": 0.00011,
    "scf_last_resid": 1.2e-8, "scf_n_iter": 14,
    "scf_cumulative_s": 380.5
  },
  "scf_trace": [ { "iter": 1, "dE": 3.1, "dP": 1.4 } ],   // 只存前 10 步
  "geometry_descriptors": {
    "coordination_number_mean": 5.6, "bond_len_std": 0.083,
    "mulliken_min": -0.91, "mulliken_max": 1.42,
    "max_displacement": 0.0021
  },
  "reference": { "level": "wB97X-D/def2-TZVP", "e_ref": -1234.5712, "delta_e": 4.3 }  // 可为 null
}
```

**关键约束**：`scf_trace` 是序列，进模型前必须压成标量（残差斜率、振荡幅度、末端残差、
ΔE 一阶/二阶差分）。原因是 TabPFN 只吃表格——这个压缩规则要在特征层定义时就写死，
不能等模型选完再补。

### 3.2 `EvalResult`（输出）— 全系统唯一出口

```jsonc
{
  "record_id": "uuid",
  "verdict": "pass | pass_with_warning | rerun | escalate | human",
  "quality_score": 78,                      // 0-100，由误差预测 + σ 推导
  "error": {
    "delta_e_pred": 4.1, "unit": "kcal/mol",
    "sigma": 1.3, "interval_90": [1.9, 6.3]  // conformal 校准后的区间
  },
  "diagnosis": [ { "label": "scf_hard_convergence", "p": 0.87 } ],  // v0.1 由规则填
  "action": {
    "type": "rerun | escalate_dft | accept | human_review",
    "params": { "scf_algorithm": "quadratic", "max_cycle": 200 },
    "cost_estimate_min": 0
  },
  "reasons": [
    { "source": "rule:SCF-003", "text": "SCF 在 6 次迭代内残差振荡幅度 > 1 个量级" },
    { "source": "model:error_head", "text": "预测偏差 4.1±1.3 kcal/mol，超化学精度" }
  ],
  "abstain": false,
  "model_version": "err-head-0.3", "calibration_version": "conformal-0.2"
}
```

**三个字段是这套系统能不能被信的底线**：

- `reasons[]` —— 没有理由的评分没人会看第二眼；
- `abstain` —— 系统必须允许说"我不知道"，否则被逼着在不懂的时候瞎判；
- `interval_90` —— 只给点估计的系统无法支撑"要不要花钱算 DFT"这种决策。

## 4. 决策策略（L4）

在 DFT 预算下选动作，本质是一个带约束的优化：

```
min  期望 DFT 调用次数
s.t. 漏放率（坏计算被判 pass）≤ ε
```

判定顺序（阈值可由用户配置）：

| 条件 | 动作 |
|---|---|
| 规则命中 `severity=critical` | `rerun` + 带 `fix_hint` 的具体参数 |
| `ΔE_pred + 1.645σ > τ_chem` | `escalate`（送高精度参考） |
| `σ > σ_hi`（模型没把握） | `human` 或 `escalate`，**不装懂** |
| 其余 | `pass` / `pass_with_warning` |

`τ_chem` 默认 1.0 kcal/mol（化学精度）。**过渡金属/开壳层体系建议放宽到 3–5 kcal/mol**，
这条需要按 `family` 分别配置，不能用单一全局阈值。

## 5. 评估协议（比模型本身更重要）

| 层 | 指标 |
|---|---|
| 规则引擎 | 覆盖率、误杀率（false reject）、平均提前判定步数 |
| 误差头 | MAE / RMSE（kcal/mol，按 family 与 method 分层）、Spearman、90% 区间实际覆盖率（conformal）、ECE |
| 决策层 | risk-coverage 曲线、AURC、固定 DFT 预算下的漏放率、DFT 调用下降比例 |
| 业务层 | 同等 τ 下 DFT 次数下降；结构优化中力计算次数（对标 PPT 第 3 页的 1/2–1/3） |

**必设四组对照**：纯规则 / 纯模型 / 规则+模型并联 / 随机选样。
最后一项对应 PPT 第 5 页提到的坑——按不确定性选样的收益可能有限，必须在相同 DFT 预算下
和随机抽样比，且单列"训练没见过的分子类型"子集。

## 6. 落地路线

### Phase 0 — 骨架（约 2 周）

- `CalculationRecord` / `EvalResult` 落地为 pydantic 模型
- Gaussian 输出解析器（先支持 `opt` + `scf` 两个 stage，够用就停）
- 规则引擎 v0：30 条规则（收敛性、虚频、方法-基组-电荷匹配、能量-梯度一致性）
- metrics harness：risk-coverage、覆盖率、分层 MAE
- 公开数据集抽样 5k 条灌通管线

**出口标准**：`evaluate()` 能稳定产出 `EvalResult`；规则引擎单独跑出第一条 risk-coverage 曲线。

### Phase 1 — 基线（约 3–4 周）

- XGBoost / MLP / TabPFN-2.5 三个基线，同一特征表、同一划分
- 误差头训练 + conformal 校准
- 输出一张对比表：**哪个模型在哪个 family 上赢规则多少**

**出口标准**：这张表能直接回答 PPT 第 14 页自己提的三个问题。

### Phase 2 — 决策与闭环（约 3 周）

- 决策策略与阈值配置
- DFT 预算实验（含随机对照）、漏放率评估
- 参考值回灌与增量更新、漂移监控

### Phase 3 — 可选：自训练 Transformer

- 只对 Phase 1 里"确实赢不了"的头做自训练多头 Transformer
- 预留的另两个头（质量评分、异常诊断）在此阶段按需挂载

**硬门槛**：Phase 1 若 TabPFN-2.5 已足够好，Phase 3 直接不做，
把资源投到规则库扩充和概率校准上。**这条比路线本身重要。**

## 7. 现在就能预见的四个风险

1. **标签稀缺**：ΔE 需要高精度参考。公开数据有，自有 TiCl4 体系没有。
   → 自有数据只能当测试集，绝不能混进训练（会数据泄漏，指标虚高）。
2. **分布外**：含过渡金属、开壳层体系在公开数据集里几乎为零。
   → 必须单列 OOD 测试集，否则指标好看但落到真实场景全崩。
3. **规则与模型冲突**：两者都出结论但不一致时谁优先？
   → 建议 `severity` 优先，同级则看 σ；冲突样本全部记录，是后续改进的主要来源。
4. **四头的诱惑**：诊断头标签最难拿，v0.1 用规则顶住，别提前做。

## 9. Phase 0 启动清单（照着做，约 2 周）

> 总原则：**先做不需要模型就能交付价值的部分，用它换取数据和信任，再用数据决定要不要模型。**

### 9.1 规则清单（半天，不写一行代码）

这是整个项目的第一件事，也是最容易被跳过的一件事。做法：把"我一眼就看出这个计算有问题"的场景全部列出来，
每条写成「触发条件 → 严重级别 → 建议动作」三元素。

| 类别 | 典型规则 | 能否直接判定 |
|---|---|---|
| A 收敛性 | SCF 未收敛即进入后续阶段、几何优化跑满步数（`Optimization stopped`）、频率计算前未做 opt、IRC 中断 | 能 |
| B 结构合理性 | 极小值点出现虚频、TS 虚频数 ≠ 1、原子间距离 < 0.5 Å、配位数突变 | 能 |
| C 方法-体系匹配 | 过渡金属用 6-31G 类基组、开壳层用 R 方法、缺色散校正、溶液体系缺溶剂模型 | 能（查表） |
| D 数值一致性 | 单点能与优化末步能量不符、能量-梯度不一致、⟨S²⟩ 自旋污染、电荷/多重度不匹配 | 能 |
| E 流程完整性 | 缺 `Normal termination`、link 断裂、内存/磁盘报错、输出被截断 | 能 |

**验收**：30 条规则，每条都带 `fix_hint`（不光说错，还要说怎么改——这是规则胜过模型的地方）。

**顺带产出**：这 30 条规则的标签集合，就是诊断头的候选标签表。初期用规则给数据打标（弱监督），
标注成本几乎为零，这是这套系统省钱的关键一步。

### 9.2 最小闭环 demo（2–3 天）

拿 2–3 份你自己手上的真实 Gaussian 输出（含 TiCl4 / 内给电子体最好，含一份有问题的更好），
把 `log → CalculationRecord → 规则 → EvalResult → 终端报告` 全线打通。

```
qchem-eval/
  pyproject.toml
  src/qchem_eval/
    schema.py               # CalculationRecord / EvalResult（pydantic）
    parsers/gaussian.py     # 只做 opt + scf 两个 stage
    rules/catalog.yaml      # 规则用 YAML 描述 + 少量 Python 谓词，不要每条写一个类
    engine.py               # evaluate(record) -> EvalResult
    cli.py                  # qchem-eval judge xxx.log
  tests/                    # 每份样例 log 一个回归测试
  data/
```

技术栈建议：**纯 Python 包 + CLI，暂时不碰 FastAPI、不碰 UI、不碰数据库**。
schema 用 pydantic，规则用 YAML + 谓词函数，测试用 pytest 把样例 log 钉成回归。

**验收**：一条命令 `qchem-eval judge xxx.log` 输出一份带理由的质检报告；
坏 log 能命中且 fix_hint 正确，好 log 判 pass 且不废话。

### 9.3 数据与参考精度确认（3 天）

- 选两个公开数据集，**先确认参考值是怎么来的**：QM9 的几何与能量不是同一级别，MD17 是单一泛函，
  跨数据集不能直接混。这一步不做，后面所有 MAE 都不可比。
- 统一单位（kcal/mol / eV / Hartree，建议内部一律 kcal/mol）与能量零点约定。
- 自有 TiCl4 数据单独划成 OOD 测试集，**绝不进训练**。

### 9.4 metrics harness（2 天，必须早于模型）

- risk-coverage 曲线、规则覆盖率、分层 MAE、90% 区间覆盖率。
- 先把"随机基线"和"纯规则基线"画进同一张图——后面任何模型都要跟这两条线比。

### 9.5 明确不要做（前两个月）

- 不搭 Transformer 训练管线
- 不做四头，诊断头用规则顶住
- 不做在线 enforcing 拦截
- 不把 LLM 放进判定路径

**关于 LLM 的位置**：第 1 页叫"量子化学 Agent"，但评测内核不需要 LLM。
LLM 只适合放在最外层的**报告叙述**和 `fix_hint` 措辞生成上。一旦让它参与判定，
结果就不可复现、无法做 risk-coverage 评估，整个"可信评测"的前提就没了。

### 9.6 第一个里程碑是什么

> 两周后，能拿一份别人算错的计算日志丢进去，输出一段让人信服的中文诊断：哪一步错了、为什么错、
> 建议怎么改、改完大概要多少机时。

这个东西能演示、能换数据、能说服合作方，比一个 R²=0.8 但没人看得懂的模型有用得多。

## 10. 修订记录

### v0.2（2026-11-17，依据《开源数据集与规则清单调研》）

调研发现开源社区已有大量可复用资产，据此修订三处：

| # | 原方案 | 修订为 | 理由 |
|---|---|---|---|
| 1 | 自研 30 条规则，约 2 周 | **基于 QMCert（MIT）扩展**，只补 Gaussian 解析、C 类方法匹配、跨阶段一致性 | QMCert 已提供经 59 个真实计算验证的判据与 PASS/WARNING/FAIL 分级；其 Gaussian 解析器未经真实输出验证，是我们的贡献点 |
| 2 | 自行设计 SCF 时序特征 | **对齐 figshare 公开数据集的 15 列**（DIIS 误差 + 总能、ΔE、α/β 自旋 HOMO−2…LUMO+2） | 有现成划分与 6 个 OOD 域，可直接产出可比基线；原作者用 GBC 而非 Transformer |
| 3 | 复核决策头按监督学习训练 | **改为策略评估**：定义 policy + 风险-覆盖率/预算实验选阈值 | "该不该送 DFT"没有客观标签，只有预算与风险偏好 |

**定位修订**：所有开源工具都只做"单条计算自检"，**无人做跨阶段一致性**（opt 末步 / 单点 / 频率三者能量对齐）。这是本系统真正的差异化，优先级高于"用 Transformer"。

**LLM 定位补充**：LLM 可作基线对照（2026 年有 deepseek-v3.2 监控 SCF 收敛、AUROC 0.909、省 27% 迭代的工作），但不进生产判定路径（不可复现、成本与延迟不可控）。

详见 `开源数据集与规则清单调研.md`。
