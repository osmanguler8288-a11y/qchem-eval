# 开源数据集与规则清单调研

> 目的：回答两个问题——(1) 现成的数据集够不够用？(2) 能不能在开源项目里直接确定规则清单？
>
> 调研日期：2026-11-17

---

## 0. 结论先行

1. **数据集够用，而且比预想的好。** 至少 5 个可直接下载的资源覆盖了有机小分子、过渡金属络合物、SCF 迭代轨迹三类，其中两个直接带"成功/失败"标签。
2. **规则清单能找到，而且已经有人把最脏的部分做完了。** `QMCert`（MIT 许可）是一个专门做量子化学计算质检的工具，判据、阈值、PASS/WARNING/FAIL 分级都是现成的。我们可以直接复用它的规则内核，而不是从零写 30 条。
3. **但"缺的只是数据集"这个判断不准确。** 真正缺的是四样东西，其中两样花钱也买不到（见第 5 节）。数据集反而是最容易解决的。

## 1. 数据集盘点

### 1.1 可直接用的五个资源

|---|---|---|---|---|---|

### 1.2 备选与补充

- **Fidelity/参考能量**：RDB7（`doi:10.5281/zenodo.6618262`）提供 16,302 个反应的 B97-D3/def2-mSVP 与 ωB97X-D3/def2-TZVP 双级别**原始 Q-Chem/MOLPRO log**，可用于验证"多保真度误差预测"这条线。
- **SCF 加速**：SCFbench（43,862 分子，辅助基密度系数）目标不同（初始猜测），但评估口径可参考。
- **官能化 TM 数据集**：tmCAT / tmPHOTO / tmBIO / tmSCO（Faraday Discuss. 2024），配体与金属的组合多样性更好。

### 1.3 数据集的三个硬缺口

1. **失败的原始 log 几乎没人公开。** VQM24 明确统计了 26 万条失败，但数据集里只有成功的 83 万条。tmQM 全是成功结构。原因很现实：失败作业没人愿意整理上传。
   → 结论：**"坏计算"的正样本必须自己造**，而且要刻意造（改小 maxcycle、故意给错多重度、错基组、扭曲初始几何）。
2. **参考精度普遍不够"高精度"。** QM9 是 B3LYP/6-31G(2df,p)，VQM24 是 ωB97X-D3/cc-pVDZ，tmQM 是 TPSSh-D3BJ/def2-SVP。这些能算"低成本 vs 中成本"的 Δ，但算不出"化学精度意义上的真值"。
   → 结论：ΔE 的真值必须自己补 DLPNO-CCSD(T) 或至少 ωB97X-D/def2-TZVP。
3. **没有一条"决策标签"。** 送不送 DFT 复核是策略问题，不是观测事实，任何数据集都不会有。

## 2. 规则清单能从哪来：三层拼装

开源社区没有一份"目的地正好是我们"的规则清单，但有三层各自成熟的来源，覆盖我们 A–E 五类中的绝大部分。

### 2.1 第一层：工作流退出码（工程层，最规范）

**AiiDA / aiida-quantumespresso** 的 exit code 是一套生产级错误分类，可直接映射成规则 ID：

| 码 | 含义 | 映射到我们 |
|---|---|---|
| 410 | 电子步未达自洽 | A-01 |
| 500 | 离子步未收敛 | A-02 |
| 501 | 离子步收敛但末次 SCF 超阈值 | A-04 |
| 502 | 离子步达最大步数仍未收敛 | A-03 |
| 510 / 511 | 离子步中电子步失败 / 末次 SCF 未收敛 | A-04 |
| 520 / 521 | BFGS 连续两次失败导致提前终止 | A-05 |
| 531 | 电子步未自洽（另一路径） | A-01 |
| 710 | 允许不收敛（`scf_must_converge=False`）时余留 | A-01 变体 |

**aiida-gaussian** 的 WorkChain 只有一条相关码：`350` = 不可恢复的 SCF 收敛错误，配合 24h 分段重提交逻辑。信息量小，但印证了"分段 + 重试"是生产做法。

**优点**：分类严谨、有编号、可直接当规则 ID 的骨架。
**局限**：只管"作业是否跑完"，不管"结果是否科学正确"。

### 2.2 第二层：数值判据（科学层，最接近我们的需求）

**`QMCert`（`github.com/sircalch/qmcert`，MIT，`pip install qmcert`）** —— 这是本次调研最重要的发现。它做的就是我们 L2 规则引擎那一层：

| 检查项 | 判据（原文） |
|---|---|
| 收敛性 | 文件中**最后一次 SCF** 的结果；优化器的收敛 banner |
| 驻点性质 | 低于 **−10 cm⁻¹** 的记为虚频；极小值需 0 个，过渡态需恰好 1 个，**≥2 个为高阶鞍点**。明确强调"收敛的优化不能作为极小值的证据" |
| 自旋污染 | ⟨S²⟩ 偏离 S(S+1) 的百分比：**>5% 警告，>10% 失败** |
| 热化学 | ZPE/H/G/S + Grimme 准 RRHO（ω₀ = **100 cm⁻¹**），并检测是否会重复施加校正 |
| 分级 | 每项 PASS / WARNING / FAIL，**总体取最差** |
| API | `assess_qm_quality(...)` → `report.overall_status` |

**两个关键细节**：
- 它在 **59 个真实 ORCA 6.1 输出**上做过验证（含刻意不收敛的作业），对照 cclib、GoodVibes 与 ORCA 自身打印值。
- **Gaussian 解析器已包含但"未在真实输出上验证"** —— 这既是缺口，也是我们最该贡献和补强的地方。

**`GoodVibes`（`patonlab/GoodVibes`，MIT）** 补充热化学侧的经验判据：
- `--imag` 打印所有虚频；`im_freq_cutoff` 可改
- `--invertifreq` 默认把 **−50 cm⁻¹ 以上**的小虚频转正
- 低频模 **<100 cm⁻¹** 需准谐振处理
- `--dup` 重复构象判据：能量 **1 µHartree**、转动常数 RMS **100 kHz**、频率 RMS **1 cm⁻¹**

**`atomate` 的 VASP Drone（pymatgen）** 提供了最好的"warning/error 双轨"结构范例：
- `warning_msgs` / `error_msgs` 两个列表，`state` 可被改成 `"error"`
- 体积变化超阈值 → warning
- 漂移量 > EDIFFG → warning："structure likely not converged to desired accuracy"
- `not s.is_valid()` → error："Bad structure (atoms are too close!)"

**`cclib`** 提供现成的收敛判定代码（三行可直接抄）：

```python
converged = bool(
    getattr(cc_data, "optstatus", False)
    and (cc_data.optstatus[-1] & ccData.OPT_DONE)
)
```

另有 `metadata["success"]`、`scfvalues` / `scftargets`、`geovalues`、`optdone` 可直接取用。

### 2.3 第三层：科学经验规则（领域层，只能从论文拿）

**Kulik「Learning from Failure」** 给出了 TM 络合物"好/坏几何"的完整可执行定义（SI Table S2）：

- 保持六配位
- 配体-金属-配体角度偏离期望值（90°/180°）不超限
- 轴向与赤道键长不对称 **≤ 0.4 Å**
- 配体定性结构保持（RMSD 与线性配体角度）

自旋判据：`⟨S²⟩ − S(S+1) > C` 判为坏，**收敛时 C = 1.0，重提交过程中放宽到 2.0**。
标签统计：几何 1,744 good / 1,733 bad（刻意平衡）；自旋 1,649 / 324。
模型效果：静态 SVM/ANN **AUC ≥ 0.95**；动态 CNN 吃时间序列，随输入步数增加而变好。
论文还给了完整的"自动驾驶"（autonomous job control）方案，与 PPT 第 5 页的主动学习是同一思路。

这类规则的价值在于：**它把"什么算坏"从口头经验变成了可仲裁的阈值**。而这正是我们最缺的东西。

## 3. 对照我们的 A–E 五类：覆盖情况

| 类别 | 覆盖率 | 来源 | 还需自己做什么 |
|---|---|---|---|
| A 收敛性 | **~90%** | AiiDA 退出码 + QMCert + cclib | 串联检查（频率前是否真做过 opt） |
| B 结构合理性 | **~80%** | QMCert（虚频）+ Kulik（配位/键长）+ atomate（原子过近） | 针对 TiCl₄ 类体系的配位几何规则 |
| C 方法-体系匹配 | **~10%** | 仅零散常识 | **几乎全自研**：基组-元素匹配表、ECP、开壳层方法、色散、溶剂模型 |
| D 数值一致性 | **~70%** | QMCert（自旋污染）+ Kulik（C 阈值） | **跨阶段一致性**：opt 末步 vs 单点 vs 频率的能量对齐 |
| E 流程完整性 | **~95%** | atomate + cclib `metadata["success"]` | 基本没有 |

**两个结论**：
- A/B/D/E 四类基本不用自己发明，拼装现成实现即可。
- **C 类（方法-体系匹配）是真空**，QMCert 明确不做这类，atomate 也不做。这恰好是"老化学家一眼看出问题"的地方，也是我们最该建护城河的规则库。

### 3.1 一个更大的空白：没有人做跨阶段一致性

所有开源工具都是**单条计算的自检**（一个 log 进来，判它好不好）。**没有一个**在做：

> 同一个体系，opt 末步的能量、随后单点能的能量、频率计算的能量，三者应该自洽。不自洽说明 link 断了、结构被改了、或读错了文件。

这正是 PPT 第 7 页说的"学习复杂的**跨阶段**特征关联"，而现有工具全部没有覆盖。**这是这套系统真正的差异化所在，比"用 Transformer"重要得多。**

## 5. 修正：「缺的只是数据集」不成立

真正缺四样，按难易排序：

| # | 缺什么 | 为什么难 | 怎么补 |
|---|---|---|---|
| 1 | 规则清单的**拼装**（不是发明） | 不难，但要人肉读五个项目的源码 | 本周可完成，见第 4 节 |
| 2 | **失败样本的原始 log** | 没人公开，VQM24 有 26 万条失败但只给统计 | **自己造**：脚本化生产失败样本（改 maxcycle / 错多重度 / 错基组 / 扭曲几何） |
| 3 | **阈值口径**（什么算坏） | 体系相关：Kulik 用 0.4 Å，QMCert 用 5%/10%，过渡金属要放宽 | 按 `family` 分级配置，先定 2 套（有机 / 过渡金属） |
| 4 | **ΔE 的真值** | 需要 DLPNO-CCSD(T) 级别参考，公开数据集最高只到 ωB97X-D3/cc-pVDZ | 自算，或降级方案：用 ωB97X-D/def2-TZVP 当"准真值"并诚实标注 |

外加一样概念性的：**决策标签根本不存在**，因为"要不要送 DFT 复核"是策略不是事实。见下节修订。

## 6. 对方案 v0.1 的三处修订

### 修订 1：规则引擎不自研，直接站在 QMCert 上

原计划"2 周写 30 条规则"。改为：**fork/wrap QMCert 作为 L2 内核**，我们只做三件增量：
1. 补 Gaussian 解析（QMCert 自己做了解析器但**从未在真实 Gaussian 输出上验证**——这是最大的现实风险，也是我们的贡献点）
2. 补 C 类方法-体系匹配规则
3. 补跨阶段一致性检查（QMCert 完全没做）

工程量从 2 周降到约 3 天，且立刻获得一个经过 59 个真实计算验证的判据基线。

### 修订 2：SCF 头的特征定义直接对齐公开那一套

不要自己发明特征。直接采用 figshare 数据集的 15 列结构（DIIS 误差 + 总能、ΔE、α/β 自旋 HOMO−2…LUMO+2），理由有三：
- 有现成的 train/val/test 与 6 个 OOD 域，可以直接跑出可比基线
- 原作者用的就是 **Gradient Boosting Classifier**（不是 Transformer）——再次印证"先别上 Transformer"
- 特征少而固定，TabPFN 也能直接吃

### 修订 3：复核决策头从「监督学习」改成「策略评估」

这是最本质的一处修订。**没有任何数据集有"该不该送 DFT"的标签**，因为它取决于预算和风险偏好，不是客观事实。所以：

- ❌ 原方案：训练一个分类器预测"是否需要复核"
- ✅ 新方案：定义 policy 函数（σ 阈值 + ΔE 预测 + 规则严重度），用**风险-覆盖率曲线 + 固定预算实验**来选阈值和证明它比随机好

这意味着第 4 类任务的工作量在"实验设计"而不在"建模"。PPT 第 13 页那句"回归结果怎么转换成评分"，本质就是这个 policy 的设计问题。

### 附带一处的自我修正

上一轮我说"LLM 不进判定路径"。补充一个例外：2026 年有工作用 deepseek-v3.2 直接从 SCF 数值日志做收敛监控，907 个 Fe 氧化物静态计算上 AUROC 0.909，节省约 27% 迭代、误终止率 3.4%。

→ 修正为：LLM **可以作为基线对照**（论文级可比对象），但仍不进生产判定路径——原因不变：不可复现、不可控成本、延迟不达标。它反而证明"纯规则检测器会误判"（该文明确指出规则组合在 FeO 上失效），支持我们"规则 + 模型并联、σ 高就回退"的设计。

## 7. 本周可做的三件事

1. **`pip install qmcert`，拿一份真实 Gaussian log 跑一遍。** 验证它的 Gaussian 解析器到底行不行——这是整个方案最大的未知数，一天内必须有答案。
2. **拉 VQM24 的 `DFT_saddles.npz`（111 MB）**，用 E-01/B-01 规则跑一遍，看虚频判据能否复现鞍点标签。这能立刻验证规则准确率。
3. **拉 figshare 的 SCF 特征集**，用原作者同款 GBC 跑一遍，得到我们自己的 risk-coverage 基线曲线。

三件事都不需要训练任何神经网络，一周内能给出"规则引擎准确率 + SCF 预警基线"两个硬数字。
