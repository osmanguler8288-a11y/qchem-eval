# 这些数据集能训练我们的 Transformer 层吗？

> 逐数据集 × 逐输出头核对。结论先说：**能喂的数据集只有一个，其余大多喂不动，而且不是因为数据量不够，是因为数据形态不对。**

---

## 0. 结论

| 结论 | 说明 |
|---|---|
| **只有 1 个数据集能直接训 Transformer** | figshare SCF 时序集，且只能训 SCF 早期预警头 |
| **其余 4 个喂不动 Transformer，但能喂基线和规则** | 不是量的问题，是"只有终点没有过程"、"只有单方法结果没有配对" |
| **最缺的标签，任何公开数据集都没有** | 见第 3 节"误差的两种类型" |
| **有一个现在就该做的动作** | 自己生成"实例级误差"标签，成本很低，且是唯一能撑起 Transformer 的标签 |

## 1. 数据集 × 输出头：匹配矩阵

| 数据集 | 质量评分头 | 误差回归头 | 异常诊断头 | 复核决策头 | SCF 预警头 | 判断 |
|---|---|---|---|---|---|---|
| **figshare SCF 时序集** | ✗ | ✗ | ○ 弱 | ✗ | **✓ 唯一直接可用** | 逐迭代序列 + 已划分 train/val/test + 6 个 OOD 域 |
| **Kulik LFF** | ✗ | ✗ | **✓ good/bad 标签** | ✗ | ✗ | 标签质量最高，但只有 3,477 条，且限八面体 TM |
| **VQM24** | ○ 弱 | ✗ | ○ 鞍点可作负样本 | ✗ | ✗ | 52,071 条鞍点是有价值的"坏计算"正样本 |
| **tmQM** | ○ 弱 | ✗ | ✗ | ✗ | ✗ | 全是成功结构，无负样本、无过程 |
| **RDB7** | ✗ | **○ 方法级偏差** | ✗ | ✗ | ✗ | 唯一三级别配对 + CCSD(T) 参考，但训的是"方法误差"不是"实例误差" |

图例：✓ 可直接训练 ／ ○ 需大量改造或只能作弱监督 ／ ✗ 无法使用

## 2. 三个致命错配

### 错配一：只有终点，没有过程

PPT 第 7 页要 Transformer「学习复杂的**跨阶段**特征关联」，第 9 页要做「序列 → 共享表示 h」。

但 tmQM、VQM24 提供的是一条记录的**最终结果**：优化好的几何 + 一堆标量性质。它们不提供：

- SCF 迭代轨迹（除 figshare 那一个）
- 几何优化轨迹（每步能量/梯度）
- 阶段边界（opt 结束在哪、freq 从哪开始）
- 同一条计算链的跨阶段对齐关系

**Transformer 的输入形态根本凑不出来。** 你能拼出来的只是一张宽表——那正好是 XGBoost/TabPFN 的主场，不是 Transformer 的。

### 错配二：只有单方法结果，没有配对

误差回归头要学的是 `ΔE = E_方法X − E_高精度参考`。这需要**同一体系、两种精度、配对**。

- tmQM：只有 TPSSh-D3BJ/def2-SVP 一层
- VQM24：只有 ωB97X-D3/cc-pVDZ 一层
- **RDB7：唯一有三层**（B97-D3/def2-mSVP、ωB97X-D3/def2-TZVP、CCSD(T)-F12/DZ 和 TZ）

但 RDB7 给的是**反应能和势垒**，不是单次计算的绝对能量，且没有 SCF 轨迹。能训"这个反应在 B3LYP 下会差多少"，训不了"这一次计算本身靠不靠谱"。

### 错配三：只有成功样本，没有失败样本

诊断头的本质是"把坏计算挑出来"，是二分类/多标签，最怕类别不平衡到 0 : N。

- tmQM：86,665 条，**全是成功优化的结构**
- VQM24：835,947 条收敛结构；26 万条失败**只统计不收录**
- figshare：有"难/易"划分，但都是有轨迹的作业

唯一带平衡标签的是 Kulik LFF（1,744 good / 1,733 bad），但规模 3,477。

## 3. 核心：误差有两种，别混为一谈

这是整份分析最重要的一点。现有数据集几乎全在服务"第一种"，而我们的 Transformer 该学的是"第二种"。

| | 方法级系统误差（method bias） | 实例级偶然误差（instance error） |
|---|---|---|
| 定义 | 方法 M 相对高精度参考的平均偏差 | 这一次具体计算，相对"方法 M 的理想结果"偏离多少 |
| 来源 | 泛函/基组本身的近似 | SCF 落到不同解、收敛到别的局部极小、自旋态选错、几何没优化好、格点不足 |
| 是否是体系的函数 | 是，基本只取决于体系和成键类型 | 否，取决于初始条件与数值细节 |
| 怎么得到 | 查表 / 跑 benchmark 统计 | 同一方法、不同初始条件，重复计算取离散度 |
| 公开数据集有吗 | **有**（RDB7、GMTKN55） | **没有，一个都没有** |
| 该用什么学 | **查表就够了，不需要 Transformer** | **这才是 Transformer 的活** |

**关键推论**：如果我们把 RDB7 拿来训"误差回归头"，训出来的是一个**方法偏差查表器**——它本质上在学"B3LYP 对 C–H 键活化会低估多少"，这件事用一张统计表就能回答，不需要 8 层注意力。而且它无法回答"这一次计算可不可信"，因为同方法的两次计算在它眼里是一模一样的。

**由此得出一个不太舒服但必须接受的判断**：按现在的数据条件，误差回归头训出来的东西，业务价值接近零。真正的价值在实例级误差，而那个标签得自己造。

## 4. Transformer 什么时候才值得训：三个门槛

按重要性排序，三条都过才动手。

### 门槛一：基线的天花板必须已经摸到

在同一个特征表、同一切分下，先跑 GBC 和 TabPFN-2.5。
**只有当它们的 risk-coverage 曲线明显不够用时**，才引入 Transformer。

参照系已经有了：figshare 那篇原作者用 **Gradient Boosting Classifier** 就跑通了 SCF 早期预警，Kulik 用 SVM/ANN 在 3,477 条上拿到 AUC 0.95。两个都是经典模型。**如果我们在同样数据上连它们的水平都达不到，Transformer 只会有更多借口，不会更好。**

### 门槛二：任务必须是真序列

Transformer 相对 GBC 的优势只在"长程依赖 + 变长输入"。所以只有满足以下之一才用：

- 输入本身是变长序列（SCF 迭代、优化步、频率模式列表）
- 需要跨阶段对齐（opt 的末几步 + freq 的头几个模 + 单点的能量）

如果特征是压好的固定长度标量，**GBC 更划算，没有争论空间**。

### 门槛三：样本量配得上参数量

序列任务的经验线：< 1,000 条序列时，Transformer 基本一定过拟合；1,000–10,000 条可以试小模型（2–4 层、d_model 64–128）；> 10,000 条才有必要上 PPT 第 9 页那种"多个 Block + 四头"。

对照现状：figshare 给的是 QM9-H1000（1,000 条极难）+ 6 个 OOD 域，量级正好在"可以试小模型但别指望碾压 GBC"的区间。

## 5. 唯一现在就能训的场景，以及该怎么训

**SCF 早期预警头**，用 figshare 那套数据。

输入形态（原作者已定好，直接沿用）：

```
每条记录 = 10 步 × 15 列
15 列 = [DIIS 误差, 总能, ΔE, α 自旋 HOMO−2…LUMO+2 (7), β 自旋 HOMO−2…LUMO+2 (7)]
```

建议的对照实验（**这才是 Phase 1 该产出的东西**）：

| 模型 | 配置 | 回答什么问题 |
|---|---|---|
| 规则阈值 | 残差斜率 + 振荡幅度 + 滑动窗拟合 | 纯规则能做到多少（这是要打败的底线） |
| GBC | 原作者同款，10 步压成 ~30 维标量 | 经典模型的上限 |
| TabPFN-2.5 | 同上，样本 ≤10k 时 | 预训练表格模型能否直接超过 GBC |
| 小 Transformer | 2 层、d_model=64、4 头、输入 10×15 | 注意力是否真的带来提升 |

四个都在同一划分、同一指标（AUROC + risk-coverage + 误终止率）下比。**这张表出来，PPT 第 14 页自己提的三个问题就有答案了**，而且是数据给的答案，不是猜的。

注意一个已被验证的坑：2026 年那篇 LLM 监控 SCF 的论文明确指出，纯规则组合（能量趋势 + 电荷残差 + 振荡检测 + 滑窗拟合）在 FeO 这类强关联体系上会误判——因为"大幅振荡但最终收敛"的轨迹很常见。所以规则基线在有机体系上可能好看，在过渡金属上会崩。**我们的 SCF 基线必须在含 TM 的 OOD 域上单独报。**

## 6. 缺的那块标签，怎么自己造

既然实例级误差没人给，就自己造。而且这件事比想象中便宜。

### 6.1 实验设计：同方法、多初始条件、看离散度

固定**同一个泛函和基组**（关键，不能变），只扰动数值相关的初始条件：

| 因素 | 水平 | 说明 |
|---|---|---|
| SCF 初猜 | HCore / minao / 上次波函数 / 随机微扰 (±0.01) | 最影响落到哪个 SCF 解 |
| 初始几何 | 平衡几何 / ±0.05 Å 随机扰动 / 另一构象 | 影响局部极小 |
| SCF 算法 | DIIS / CDIIS / quadratic / damping 0.7 | 影响收敛路径与终态 |
| 积分格点 | coarse / fine / ultrafine | 影响数值噪声 |
| 自旋态 | 目标态 ± 相邻态（仅开壳层） | 最容易错的一维 |

对同一体系跑 N 个组合，得到能量集合 {E₁…E_N}，定义：

```
σ_instance = std(E_i)            # 实例级不确定度
ΔE_instance = |E_i − min(E)|     # 单次计算偏离该体系最佳值的量
```

**σ_instance 就是 Transformer 唯一学不到、也最该学的标签。**

### 6.2 成本估算（这是可行性关键）

小分子 def2-SVP 级别的**单点**计算，几十秒到几分钟。

- 5,000 个分子 × 4 种初猜 = 20,000 次单点
- 单机并行按 20 核、每次 2 分钟算 → 约 33 机时（可在一夜内跑完）
- 若扩展到 16 种组合 → 80,000 次，约 130 机时，一个周末

**结论：这个标签生成器的成本比训练一个 Transformer 低一个数量级，但它的价值高得多。**

### 6.3 副产品：它顺便定义了"什么叫坏计算"

拿到 σ_instance 的分布之后：

- `|ΔE_instance| > 1 kcal/mol` → 这次计算不可信（具体阈值按 family 定）
- σ_instance 高的体系 → 就是"该送 DFT 复核"的体系

这直接把方案里那个"没有决策标签"的问题**变成了可计算的问题**：不需要人工标"该不该复核"，只需要看这次计算离它自己所在分布的中心有多远。

### 6.4 还可顺手拿到的东西

同一批重复计算，天然构成失败样本库：初始条件足够极端时一定有作业不收敛 → **这就是第 1 节说的"没人公开的失败 log"，自己造出来了**。

## 7. 对路线的影响

### Phase 0 增加一项（约 3 天）

`σ_instance` 标签生成器：脚本化"同方法多初始条件"批量提交 + 结果聚合。产出 2 万条带实例级 σ 的记录。

### Phase 1 的重心从"训模型"改为"证明模型有存在必要"

产出物不是"一个 Transformer"，而是**第 5 节那张四模型对照表**。如果小 Transformer 没赢 GBC，结论就写"不训"，并且这是个**有价值的负结果**——省下来的算力投到规则库和 σ 校准上。

### Phase 3 的触发条件写死

只有满足全部三条才启动自训练 Transformer：

1. GBC 与 TabPFN 的 risk-coverage 曲线在 OOD 域上明显下降
2. 任务被确认是真序列（跨阶段对齐或变长轨迹）
3. 训练样本 > 1,000 条序列（含自造的 σ 标签集）

否则 Phase 3 砍掉，把 Transformer 只保留在"SCF 预警"这一个窄场景上。

---

## 8. 一句话总结

> 公开数据集能帮我们把**规则引擎和经典模型基线**建起来，能直接训 Transformer 的只有一个（SCF 时序）。
> Transformer 真正该学的"实例级误差"没人给，但它生成成本很低——**先造标签，再决定要不要造模型。**
